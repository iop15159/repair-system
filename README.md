## 報修清單篩選

- 清單上方提供「全部／高／中／低」按鈕，預設為「全部」；目前選項以深綠底與外框標示，並提供 `aria-pressed` 狀態。
- 篩選僅使用網頁已讀取的最近 20 筆報修，不會額外查詢資料庫，也不代表搜尋全部歷史紀錄；沒有符合項目時會顯示提示。
- 高緊急程度的標籤改為紅字、淡紅底；中、低標籤維持原樣。
- 按「重新整理」或成功送出報修後會重新讀取最近 20 筆，並保留目前的篩選選項；讀取失敗時保留上次成功讀取的清單。
- 此次僅修改網頁與本說明，未變更資料庫、資料欄位或 `supabase/` 中任何檔案。

## 手機確認方式

1. 使用本 PR 分支的本機預覽（或合併部署後的 GitHub Pages），滑到「最近的通報」。PR 未合併前，main 的公開網站仍是舊版。
2. 確認預設「全部」為深綠底，依序點選「高／中／低」，清單只顯示相符紀錄，選取狀態同步改變；「高」標籤應為紅色。
3. 若某緊急程度無紀錄，應顯示沒有符合報修的提示；點「全部」可恢復所有已載入紀錄，順序仍為新的在上。
4. 點「高」後再按「重新整理」，確認仍停留在「高」；直向手機畫面中四個篩選按鈕應清楚可點。
5. 若使用瀏覽器開發工具的 Network 面板觀察，切換篩選不應新增 `repair_requests` 請求；只有初次載入、重新整理或成功送出後才讀取清單。
