## PWA 安裝與離線使用

- 連線開啟 GitHub Pages 後，Android Chrome／桌面 Chrome 或 Edge 可從瀏覽器選單安裝；瀏覽器提供安裝提示時，頁面會出現「安裝報修登記」按鈕。iPhone 請在 Safari 使用「分享 → 加入主畫面」。安裝提示是否出現取決於瀏覽器。
- 首次使用須連網，等待 Service Worker 安裝完成。之後可離線開啟已快取的介面；清單讀取與報修送出仍需連線。未送出的表單不會持久儲存、自動排隊或補送，關閉或重新整理前請先處理未送出的內容。
- 快取僅包含靜態網頁、圖示及 Supabase CDN 程式庫，不持久快取報修資料或 API 回應；離線冷啟動無法查看先前清單。CDN 首次載入失敗時，須連線重新整理以準備完整介面。
- manifest 與 Service Worker 使用相對路徑，支援 `/repair-system/` GitHub Pages 子路徑；正式環境需要 HTTPS，本機測試可用 localhost，不能直接用 file://。
- 修改快取內的靜態資源時須遞增 `sw.js` 的快取版本。更新下載後，關閉所有舊版分頁及已安裝視窗再開啟，才會使用新版。
- 驗收：在線上開啟一次，再離線重新整理確認介面可開啟、離線提示出現且送出不會寫入；恢復連線後手動重新整理清單。資料庫與 `supabase/` 未變更。

## 報修清單篩選

- 清單上方提供「全部／高／中／低」按鈕，預設為「全部」；目前選項以深綠底與外框標示，並提供 `aria-pressed` 狀態。
- 篩選僅使用網頁已讀取的最近 20 筆報修，不會額外查詢資料庫，也不代表搜尋全部歷史紀錄；沒有符合項目時會顯示提示。
- 高緊急程度的標籤改為紅字、淡紅底；中、低標籤維持原樣。
- 按「重新整理」或成功送出報修後會重新讀取最近 20 筆，並保留目前的篩選選項；讀取失敗時保留上次成功讀取的清單。
- 此次僅修改網頁與本說明，未變更資料庫、資料欄位或 `supabase/` 中任何檔案。

## 手機確認方式

1. 使用本 PR 分支的本機預覽（或合併部署後的 GitHub Pages），滑到「最近的通報」。PR 未合併前，main 的公開網站仍是舊版。
2. 確認預設「全部」為深綠底，依序點選「高／中／低」，清單只顯示相符紀錄，選取狀態同步改變；「高」標籤應為紅色。
3. 若某緊急程度無紀錄，應顯示沒有符合報修的提示；點「全部」可恢復所有已載入紀錄，順序仍為新的在上。
4. 點「高」後再按「重新整理」，確認仍停留在「高」；直向手機畫面中四個篩選按鈕應清楚可點。
5. 若使用瀏覽器開發工具的 Network 面板觀察，切換篩選不應新增 `repair_requests` 請求；只有初次載入、重新整理或成功送出後才讀取清單。
